# 00 总体架构与开发规范

## 1. 系统定位

**模型中转站**：统一 LLM API 网关（功能对标 NEWAPI）。核心能力：

- OpenAI 兼容转发：`/v1/chat/completions`、`/v1/models`，客户端零改造
- 多渠道接入：OpenAI 兼容基类覆盖 90% 厂商 + Anthropic/Gemini/星火 原生适配
- 拼车：多用户共享渠道池，用户/令牌双层配额，用量精确归因
- AUTOFIT：入站 A社/OpenAI/Gemini 格式自动识别，出站自动转上游原生格式
- 计费：模型定价、兑换码、充值（收款码）、用量统计
- 通知：短信 / 邮箱 / 额度告警 / 渠道异常告警
- 自检：启动完整性检验、渠道健康探测、状态面板

## 2. 总体架构

```
                    ┌────────────────────────────────────────────────┐
                    │              relay-server (bin)                │
  ┌───────────┐     │  ┌────────────┐   ┌──────────┐   ┌──────────┐  │
  │ 管理后台    │──▶│  │ relay-api   │──▶│ relay-store│  │ relay-health │
  │ (TS前端)   │     │  │ 路由/鉴权   │   │ SQLite    │   │ 自检/探测   │
  └───────────┘     │  └─────┬──────┘   └──────────┘   └──────────┘  │
                    │        │                                        │
  ┌───────────┐     │  ┌─────▼────────┐   ┌─────────────┐            │
  │ 客户端     │──▶│  │ relay-autofit │──▶│ relay-gateway│──▶billing  │
  │ A社/OpenAI│     │  │ 入站识别/转换  │   │ 请求管线     │   │notify   │
  └───────────┘     │  └──────────────┘   └──────┬──────┘   │tokenizer│
                    │        ┌──────────────────┴────┐      └─────────┘
                    │        ▼                       ▼
                    │  relay-provider           relay-tokenizer
                    │  (20+ 渠道适配)           (BPE 本地计数)
                    └────────┬────────────────────────┘
                             ▼ 上游模型厂商
```

**分层原则**：
- 上层依赖下层，依赖单向（见 README 依赖图）
- 业务层（gateway/billing/provider）不感知 HTTP；api 层只做路由与序列化
- store 用 trait 抽象，可换存储实现

## 4. 编码规范

### 4.1 错误处理
- 所有业务错误 → `relay_core::AppError`（见 03 文档），禁止在业务层直接返回 HTTP 状态
- 转换：`impl IntoResponse for AppError` 只在 relay-api 层实现

### 4.2 日志
- 统一 `tracing`，启动时初始化 `tracing_subscriber`（env-filter）
- 转发请求关键点打点：`info!(token_id, channel_id, model, "forward start")` / `"forward done"`（含耗时）
- 禁止 `println!`（除启动横幅）

### 4.3 测试
- 每个 crate 单元测试：核心逻辑（转换矩阵/配额计算/限流）必须覆盖
- 集成测试：`scripts/test.js`（Node，起服务后打 API）
- 测试数据用 `%TEMP%` 独立目录 + `DOCPI_DISABLE_CAPTCHA` 同款思路（本仓库为 `RELAY_DISABLE_CAPTCHA=1`）

### 4.4 配置
- 环境变量前缀 `RELAY_`：`RELAY_PORT`、`RELAY_DATA_DIR`、`RELAY_ADMIN_PASSWORD`、`RELAY_DISABLE_CAPTCHA`
- 密钥类（渠道 API Key、短信 AccessKey）一律加密存储（见 01 文档），日志禁止输出

### 4.5 时间
- 一律 `chrono::Local` 的 `"YYYY-MM-DD HH:MM:SS"` 字符串存库（与 DocPI 一致，方便阅读）

## 5. 全局约定

| 约定 | 值 |
|------|-----|
| 令牌前缀 | `sk-` + 24 位随机（`rand` 生成，仅创建时展示一次） |
| 兑换码格式 | `REDEEM-` + 4×4 大写字母数字 |
| 金额单位 | 元（REAL），价格按每 1M token |
| 配额单位 | token 数（INTEGER） |
| 分页 | 管理列表统一 `?page=1&page_size=20`，返回 `{items, total}` |
