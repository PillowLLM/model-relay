# 02 认证与权限

## 1. 两套认证体系

| 体系 | 适用 | 凭证 | 生命周期 |
|------|------|------|---------|
| 管理端 Session | 管理后台（浏览器） | Cookie + 服务端内存 session | 7 天 |
| API 令牌 | 客户端调用 `/v1/*` | `Authorization: Bearer sk-xxx` 或 `?token=` | 可设过期 |

## 2. 管理端登录（复用 DocPI 已验证方案）

### 2.1 图形验证码

```rust
// relay-api/src/captcha.rs
pub struct CaptchaStore { map: Mutex<HashMap<String, (String, Instant)>> }  // id -> (答案, 过期5min)
// GET /api/auth/captcha -> { "id": "...", "image": "data:image/png;base64,..." }
// 手写点阵 PNG（不引第三方库，DocPI 同款）：4 位数字 + 噪点
// 登录成功后立即作废该 captcha_id（防重放）
```

### 2.2 密码哈希

```rust
// scrypt：N=2^14, r=8, p=1, 输出 64 字节（与 DocPI 完全一致）
pub fn hash_password(pw: &str) -> String;   // base64(salt16 + hash64)
pub fn verify_password(pw: &str, stored: &str) -> bool;
```

### 2.3 登录流程

```
POST /api/auth/login {username, password, captcha_id, captcha}
  1. 校验验证码（错 → 400 "验证码错误"）
  2. 查用户（无 → 400 "用户名或密码错误"）
  3. verify_password（错 → 400 同上；防爆破：同 IP 5 次/分钟限速）
  4. 用户 status=0 → 403 "账号已禁用"
  5. 生成 session（内存 HashMap，id 随机 32 字节，Set-Cookie: relay_session=xxx; HttpOnly; Path=/; Max-Age=604800）
  6. 返回 { user: {...} }（不含密码哈希）
```

```rust
// relay-api/src/auth.rs
pub struct SessionStore { map: Mutex<HashMap<String, (i64, Instant)>> }  // session -> (user_id, 过期)
// 中间件：从 Cookie 取 session → 加载 user → 注入 extractor
pub struct AdminAuth(pub User);     // 要求 role=admin，否则 403
pub struct UserAuth(pub User);      // 任意登录用户
pub struct OptionalAuth(pub Option<User>);
```

### 2.4 管理端点鉴权矩阵

| 端点前缀 | 要求 |
|----------|------|
| `/api/admin/*` | AdminAuth |
| `/api/auth/me` / `/api/auth/me/avatar` | UserAuth |
| `/api/recharge/*` / `/api/redeem` | UserAuth |
| `/api/usage/my*` | UserAuth（只能查自己） |
| `/api/auth/captcha` / `/api/auth/login` | 公开 |

## 3. API 令牌（客户端）

### 3.1 生成

```
POST /api/admin/tokens {name, quota_limit?, expired_at?}
  → 生成明文：sk- + 24 位随机（rand::alphanumeric）
  → 存 key_hash = sha256(明文)
  → 返回 { token: "sk-xxxx", ... }   // 明文仅此一次
```

### 3.2 校验（转发链路第一步）

```rust
pub fn parse_bearer(headers) -> Option<String>;   // Bearer sk-xxx
pub fn parse_query_token(uri) -> Option<String>;  // ?token=sk-xxx
// gateway 流程：
//   1. sha256(明文) → store.get_token_by_hash
//   2. token.status=0 → 401 "令牌已禁用"
//   3. expired_at 已过 → 401 "令牌已过期"
//   4. user.status=0 → 403 "账号已禁用"
//   5. 通过 → 加载 user + group
```

### 3.3 令牌管理（管理端）

| 接口 | 说明 |
|------|------|
| `GET /api/admin/tokens?user_id=&page=` | 列表（含用量） |
| `POST /api/admin/tokens` | 创建（返回明文一次） |
| `DELETE /api/admin/tokens/{id}` | 删除 |
| `PUT /api/admin/tokens/{id}/status` | 启停 |
| `PUT /api/admin/tokens/{id}` | 改额度/过期 |

## 4. 分组授权（NEWAPI 同款）

```
用户 ──belongs_to──▶ 分组(users.group_id)
渠道 ──granted_to──▶ 多个分组(channels.group_ids = "1,2,3")
```

**可用渠道判定**：`channels.group_ids 包含 user.group_id` 且 `channels.status=1`。

| 接口 | 说明 |
|------|------|
| `GET/POST/PUT/DELETE /api/admin/groups` | 分组 CRUD（含倍率 quota_multiplier） |
| `GET/POST/PUT/DELETE /api/admin/users` | 用户 CRUD（含 group_id 分配） |

**计费倍率**：`实际费用 = 原价 × user.group.quota_multiplier`（NEWAPI 同款，拼车差异化定价）。

## 5. 初始管理员

- 启动时若 `users` 表无 admin → 创建：`RELAY_ADMIN_USERNAME`（默认 admin）/ `RELAY_ADMIN_PASSWORD`（**必设**，无默认，缺失则启动自检失败——见 10 文档）
- 首次登录强制提示修改密码（前端引导，后端不强制）

## 6. 安全清单

- [ ] Cookie HttpOnly + SameSite=Lax
- [ ] 登录限速（IP 5 次/分钟）
- [ ] 密码 scrypt，绝不落明文/可逆
- [ ] 令牌只存哈希；明文仅创建时返回一次
- [ ] 管理 API 全部 AdminAuth（除登录/验证码）
- [ ] 用户只能查自己的用量/充值
- [ ] 验证码一次性（用后即焚）
