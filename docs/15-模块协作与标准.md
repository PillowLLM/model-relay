# 15 模块协作与标准

> 本文档回答「每个模块怎么和其它模块联合」：完整时序图、调用关系、文件标准、参数约束汇总。

## 1. 模块调用关系总览

```
relay-api ──调用──▶ gateway ──调用──▶ autofit（入站识别/出站转换）
                    │        └──▶ provider（渠道适配）──▶ 上游
                    │        └──▶ tokenizer（前置估计）
                    ├──调用──▶ billing ──▶ store
                    │              └──▶ notify（事件：quota_low 等）
                    ├──调用──▶ store（令牌校验/用量落库）
relay-health ──调用──▶ provider（探测）──▶ store（状态）
                  └──调用──▶ notify（channel_down 告警）
relay-api ──调用──▶ notify（充值/短信直发）
```

**依赖方向**：api → gateway → (billing/provider/tokenizer) → store；health 独立旁路；notify 只被 api/billing/health 调用。

### 2.2 流式转发

```
客户端 ←──SSE── relay-api ←──StreamEvent── relay-gateway ←──上游 SSE 逐块── relay-provider
                 每块经 autofit 转换（OpenAI⇄A社 事件映射，见 14 文档 C4）
                 首个 usage/终止事件 → billing.record_usage → 落库
```

### 2.3 健康探测 + 告警（relay-health 旁路）

```
tokio 周期任务（5min）                      
  relay-health ──list_models()──▶ 每渠道（并发，3s 超时）
       │ 成功 → store 更新（延迟/失败率）→ failures 清零
       │ 失败 → failures+1；>=5 且 auto_ban → channel.status=0
       └──异常──▶ notify.send(channel_down) ──▶ 短信/邮件
```

### 2.4 充值到账（收款码 + 自动回调）

```
用户 ──POST /api/recharge/order──▶ relay-api ──▶ notify(pay) 生成订单+收款码
用户扫码支付 ──▶ 支付宝/微信回调 ──▶ relay-api /api/pay/notify/{method}
  ├─ 验签 → 订单状态 paid → billing.add_quota(user) → usage 审计落库
  └─ notify.send(payment_success) ──▶ 短信/邮件通知用户
```

### 2.5 兑换码

```
用户 ──POST /api/redeem {code}──▶ relay-api ──▶ store.get_redeem_code
  ├─ 不存在/已用/过期 → 400
  └─ 事务：code.status=1 + users.used_quota -= quota（加额度）→ 200 {quota}
```

## 3. 文件标准（上传校验）

| 文件 | 允许格式 | 最大 | MIME 校验 | 其他 |
|------|---------|------|-----------|------|
| BPE 词表 | `.tiktoken`（OpenAI）、`.bpe`（GPT-2） | 50MB | `text/plain` 或 octet-stream | 格式解析校验 + sha256 checksum 入库 |
| 收款码图片 | PNG / JPG / WEBP | 2MB | `image/*` | 管理端上传，存 uploads/ |
| 头像 | PNG / JPG / WEBP | 2MB | `image/*`（data URL） | 转 base64 存库 |

**.tiktoken 文件格式**（OpenAI cl100k_base/o200k_base）：
```
每行： "<token_id> <token_bytes_base64>"
示例： 0 Ig==
       1 AA==
       2 ABM=
       3 BQ==
```

**.bpe 文件格式**（GPT-2/llama 系）：
```
每行： "<rank> <token_bytes>"（token 用可见字符或 \uXXXX 转义）
```

**词表文件校验伪代码**（relay-tokenizer + relay-health 共用）：
```
1. 首行必须可解析为 (u32, bytes)
2. 行数 >= 1000（防止空文件/损坏）
3. 全部行解析成功 → 通过；否则 400 + 不入库
4. 入库前计算 sha256 存 checksum；启动自检重算比对
```

## 4. 参数约束汇总（全系统）

| 参数 | 约束 |
|------|------|
| username | 3–32 字符，`[a-zA-Z0-9_@.]` |
| password | 8–64 字符 |
| display_name | ≤32 字符 |
| email / phone | ≤64 字符，格式宽松校验 |
| 渠道 name | ≤32；base_url ≤256（须 http/https）；api_key ≤512 |
| 渠道 type | 枚举白名单（见 01 文档 channels.type） |
| model 名 | ≤64 字符 |
| messages | 1–512 条；单条 content ≤128KB；整个请求体 ≤4MB |
| max_tokens | 1–1,000,000；缺省 4096 |
| temperature | 0–2；top_p 0–1 |
| stop | ≤4 项 × ≤64 字符 |
| tools | ≤128 项；parameters 为合法 JSON Schema |
| 令牌名 | ≤32 |
| 兑换码 | `REDEEM-` + 16 位大写字母数字（4-4-4-4 分隔） |
| 批量导入 | ≤100 条/次 |
| 充值档位 | settings `recharge_plans` JSON：`[{"id":1,"amount":10,"quota":10000},...]` |
| 分页 | page ≥1，page_size 1–100（缺省 20） |
| 请求体大小 | 管理 API ≤4MB；转发 API ≤8MB（图片 base64 场景） |

## 5. 限流参数（gateway 内置）

| 维度 | 默认 | 配置键 |
|------|------|--------|
| 每令牌并发 | 10 | settings `token_concurrency` |
| 每用户 RPM | 60 | settings `user_rpm` |
| 每渠道并发（拼车池保护） | 20 | settings `channel_concurrency` |
| 登录限速 | 5 次/分钟/IP | 硬编码 |

限流实现：内存滑动窗口（`HashMap<key, VecDeque<Instant>>`，定期清理），单实例足够。

## 6. 模块间事件清单（解耦约定）

| 事件 | 产生方 | 消费方 | 触发时机 |
|------|--------|--------|---------|
| `quota_low` | billing | notify | 额度 ≤20% |
| `quota_exhausted` | billing | notify | 额度耗尽（429） |
| `payment_success` | api（回调） | notify | 充值到账 |
| `channel_down` | health | notify + store | 渠道自动禁用 |
| `token_created` | api | 无（前端直接拿明文） | 创建令牌 |
