## 多人协作认领规则

**每个模块 = 一篇独立文档 = 一个 Rust crate**，按模块认领、互不阻塞，人多人少都行：

| 认领 | 模块文档 | 说明 |
|------|---------|------|
| 任认领 | 01 数据模型 | 可最先开工 |
| 任认领 | 03 核心类型与配置 | 可最先开工 |
| 任认领 | 04 渠道模块 / 05 AUTOFIT / 06 Token 计数 / 07 请求管线 / 02 认证 / 08 计费 / 09 通知 / 10 自检 | 每个模块一人，独立开发 |
| 前端多人 | 11 管理 API 与前端 | 页面级认领（登录/渠道/令牌/用户/仪表盘…每人一个页面） |
| 任认领 | 12 部署方案 | M1 后介入 |
| 任认领 | 13 开发路线图 | 项目负责人维护 |

**协作铁律**：
1. **文档即沟通**：接口有疑问只改 14 文档并通知大家，不私聊
2. 后端按依赖顺序实现（见下），但**文档阅读完全并行**
3. 前端只看 14 接口契约 + 11 文档，用 mock 先行，不等后端
4. 每个模块交付 = 文档验收清单全勾 + 单测通过

## 模块依赖顺序（实现顺序）

```
relay-core → relay-store → relay-provider → relay-autofit → relay-tokenizer
     → relay-billing → relay-gateway → relay-notify → relay-health → relay-api → relay-server
```

依赖单向：上层只依赖下层，禁止反向依赖。
