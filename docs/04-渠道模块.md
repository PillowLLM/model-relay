# 04 渠道模块（relay-provider）

## 1. 职责

- 屏蔽上游协议差异，提供统一异步接口
- 渠道 CRUD、批量导入、健康探测、失败自动禁用
- 模型映射（客户端模型名 → 渠道模型名）

## 2. Provider trait

```rust
// crates/relay-provider/src/lib.rs
#[async_trait]
pub trait Provider: Send + Sync {
    fn type_name(&self) -> &str;                          // "openai" / "anthropic" / ...
    async fn chat(&self, req: &CanonicalRequest, chan: &Channel) -> Result<CanonicalResponse, AppError>;
    async fn chat_stream(&self, req: &CanonicalRequest, chan: &Channel)
        -> Result<Stream<Item = Result<StreamEvent, AppError>>, AppError>;
    async fn list_models(&self, chan: &Channel) -> Result<Vec<String>, AppError>;  // 健康探测用
}

// 注册表：type -> Box<dyn Provider>（懒加载或全量构造均可，Provider 内部无状态）
pub struct ProviderRegistry { map: HashMap<String, Box<dyn Provider>> }
impl ProviderRegistry {
    pub fn default() -> Self;                             // 注册全部内置 Provider
    pub fn get(&self, type_name: &str) -> Result<&Box<dyn Provider>, AppError>;
}
```

## 4. 渠道 CRUD（管理 API）

| 接口 | 说明 |
|------|------|
| `GET /api/admin/channels?page=&type=&keyword=` | 列表（API Key 脱敏返回 `sk-****abc`） |
| `POST /api/admin/channels` | 创建 `{name,type,base_url,api_key,models,model_mapping,priority,weight,group_ids,...}` |
| `PUT /api/admin/channels/{id}` | 更新（api_key 留空 = 不修改） |
| `DELETE /api/admin/channels/{id}` | 删除（日志保留） |
| `PUT /api/admin/channels/{id}/status` | 启停 |
| `POST /api/admin/channels/batch` | 批量导入 `[{...}, ...]`（NEWAPI 同款，逐条校验，返回成功/失败数） |
| `POST /api/admin/channels/{id}/test` | 测试连通（调 list_models，返回延迟与结果） |

**脱敏**：API 列表接口返回 `api_key_masked = "sk-****" + 末尾4位`。

## 5. 渠道选择算法（gateway 调用）

```
输入：可用渠道集合（status=1 且 group_ids 含用户组）
1. 过滤：channels.models 为空 或 包含请求模型（经 model_mapping 映射后）
2. 排序：priority DESC → weight 轮询（同 priority 内按权重 round-robin，游标存内存 AtomicUsize）
3. 排除：health 探测失败的（cooldown 60s 内不选）
4. 返回渠道列表（供重试/故障转移逐个尝试）
```

```rust
// relay-provider/src/selector.rs
pub struct ChannelSelector { cursor: AtomicUsize }
impl ChannelSelector {
    pub fn pick<'a>(&self, candidates: &[&'a Channel]) -> &'a Channel;  // 按权重轮询
}
// 权重轮询：candidates 按 weight 展开成加权环（weight=3 → 出现3次），游标取模
```

## 7. 失败计数与自动禁用（NEWAPI 同款）

```rust
// relay-health 模块持有（见 10 文档）：
//   channel_failures: Mutex<HashMap<i64, (u32, Instant)>>   // 渠道id -> (连续失败数, 上次时间)
// 规则：
//   1. 请求失败（5xx/超时/连接错误）→ failures+1
//   2. failures >= 5 且 channels.auto_ban=1 → 自动 status=0，触发 notify(channel_down)
//   3. 成功 → 清零
//   4. 管理端可手动恢复（PUT status=1）
```
